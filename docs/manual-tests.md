## 共通の準備

1. `npm run build` の後に `npx vite preview --port 4317 --strictPort` で起動し、http://localhost:4317 を Microsoft Edge（最新版）で開きます。
2. OS の表示の設定を「ライト」と「ダーク」に切り替えて、それぞれで確かめます（アプリは OS の設定に追従する。NFR-UX-001）。
3. 画面の幅は、1280 CSS ピクセル以上と 320 CSS ピクセル相当（開発者ツールのデバイスのエミュレーション）の 2 つで見ます。
4. 照合に使う資料（出典台帳）:
   - SRC-008 Microsoft Surface Trademark Guidelines（January 2025 V2.0）: https://cdn-dynmedia-1.microsoft.com/is/content/microsoftcorp/microsoft/mscle/documents/presentations/Microsoft_Surface_trademark_guidelines_2025V2.0.pdf
   - SRC-005 Fluent 2（Typography・Color）: https://fluent2.microsoft.design/typography 、https://fluent2.microsoft.design/color
   - SRC-009 Surface のページ: https://www.microsoft.com/en-us/surface
5. 判定は「合格」「不合格」「判定不能（理由）」のどれかで記録し、不合格・判定不能は画面のスクリーンショットを `work/runs/<run-id>/evidence/` に残します。

- 受入基準: ブランドの見た目（トーン、色、タイポグラフィ、ロゴの使い方）が、Surface 商標ガイドライン 2025（SRC-008）、Fluent 2（SRC-005）、NFR-UX-004 と NFR-UX-005 に一致していることを、目視で確かめる。
- 前提: 共通の準備。公式のロゴファイルは設定しない（Q-004 B でライセンスがないため。ロゴを設定したときの確認は IT-004）。

| 2 | 主 CTA と、App2 の主操作のボタン（企画の確定、見積の提出・承認、素材登録の確定）を見る（ライト・ダーク） | 背景がライトで Microsoft ブルー（PARAM-011: #0067B8）、ダークで PARAM-020（#2A66B2）のピル形。ブランドの色が大きな面に使われすぎていない（SRC-005 Color の「ブランドの色はボタンと CTA に使う」） |

- 注（転記時に追記。要求定義書 Q-008）: 手順 6 のワードマークの表示そのものが商標上許されるかは Q-008 で利用者の回答待ちです。この手順では、ワードマークが画像・図形でない文字列で、Microsoft シンボルと組み合わされていないこと（AC-095）だけを確かめ、商標の該当性は判定しません。

## IT-003 NFR-UX-004 AC-094 製品が落ち着いた金属色で、暗い面の上でも輪郭が見分けられる

- 受入基準: 3D の製品ビューと 2D の製品図・構成図の製品が、SRC-009 で確かめた製品色 Dune（#F9F7F1）、または [ASSUMPTION] として置く Platinum・Black・Sapphire（色の値は SRC-009 で未確認。§10.3）に見える落ち着いた金属色で塗られ、App1 のヒーロー・カードの暗い面（PARAM-022）の上でも製品の輪郭が背景に埋もれず見分けられることを、目視で確かめる。
- 前提: 共通の準備。

| # | 手順 | 期待結果（合格の条件） |
|---|---|---|
| 1 | App1 のヒーローの製品のビジュアルを見る（ライト・ダーク） | 製品が Dune（#F9F7F1）または Platinum・Black・Sapphire に見える、落ち着いた金属色（彩度の高い原色・蛍光色でない）。暗い面（#0A1522・#021C3F）の上で、製品の外形（天板・ヒンジ・画面の縁）が背景と見分けられる |
| 2 | App1 で表示方法を 2D にし、2D の製品図を見る | 1 と同じ製品色で塗られ、置かれた面（カード・ヒーロー）の上で輪郭が見分けられる |
| 3 | App1 で表示方法を 3D にし、製品を回転させて正面・側面・背面を見る | どの向きでも製品色が金属色に見え、暗い面の上で輪郭が背景に埋もれない（Black の場合も縁・ハイライトで外形が分かる） |
| 4 | App1 の P-2 の 2D 構成図と、App2 の 2D・3D の表示に製品が描かれていれば、それを見る | 1 と同じ製品色で、背景に埋もれない |
| 5 | 「動きを減らす」設定を有効にして 1〜3 を見る | 静止した表示でも製品色と輪郭が同じように見分けられる |

- 記録: 使われていた製品色の呼び名（Dune／Platinum／Black／Sapphire）を書きます。Platinum・Black・Sapphire は色の値が未確認の仮置き（[ASSUMPTION]）なので、色の値の正しさは判定せず、「落ち着いた金属色に見えること」と「輪郭が見分けられること」だけを判定します。

## IT-004 NFR-UX-005 AC-097 公式のロゴのクリアスペース・無改変・版（条件付き・対象外）

- 受入基準: 公式のロゴファイルを使うとき、ロゴの周囲に Microsoft シンボル 1 個分以上のクリアスペースがあり、ロゴが改変（色・形・効果の変更）されず、単一行版（狭い所は積み重ね版）が使われていることを、SRC-008 と目視で照合する。
- 状態: 条件付き・対象外（Q-004 は B で回答済み。ライセンスがなく公式ロゴは使わない）。AC-096 の公式ロゴ設定が有効になったときだけ実施します。
- 前提: 公式ロゴを使う設定（AC-096）が有効で、公式のロゴファイル（明るい背景用のグレーのロゴタイプ、暗い背景用の白のロゴタイプ）が設定で指定されている（AC-096）。

| # | 手順 | 期待結果（合格の条件） |
|---|---|---|
| 1 | シェルのヘッダーと App1 のヒーローのロゴを、SRC-008 の Clear space の頁と並べて見る | ロゴの周囲（上下左右）に、Microsoft シンボル 1 個分以上の何もない空き（文字・図形・端が入らない）がある |
| 2 | ロゴを SRC-008 の Logo Usage の見本と並べて見る（ライト・ダーク、拡大表示も） | 色・形・縦横比・効果（影・グラデーション・縁取り・回転）が見本から変えられていない |
| 3 | 背景の明暗を見る | 暗い面（ヘッダー帯・ヒーロー）には暗い背景用（白のロゴタイプ）、明るい面には明るい背景用（グレーのロゴタイプ）が使われている（SRC-008 Trademark color） |
| 4 | 幅 1280 CSS ピクセル以上と 320 CSS ピクセル相当で見る | 通常は単一行版、狭い所では積み重ね版が使われ、どちらもクリアスペースが保たれ、欠けない |
