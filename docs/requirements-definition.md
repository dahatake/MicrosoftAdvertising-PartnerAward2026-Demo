## 1. 概要

### 1.1 事業背景

広告代理店（ダミー組織: Microsoft Advertizing Tokyo 畠山支店）のデモとして、同じ題材（架空の製品 Microsoft Surface Ultra）で、(1) 一般コンシューマー向けの広告キャンペーンサイト（App1）と、(2) 広告企画から展開後の利用状況までを管理する広告コンテンツ素材管理システム（App2）を 1 つの画面から切り替えて見せる。App1 は、いつでもどこでも Copilot と Prompt でアプリ・Web・動画コンテンツの制作を楽しみたいクリエイターとソフトウェアエンジニアに、最強の没入感と最高のリッチなエクスペリエンスを伝え、公式サイトへ誘導する。App2 は広告代理店の業務（企画→見積→制作→展開→利用状況）の情報を、関係が分かる形で見せる。出典: SRC-001、SRC-002。

Surface Ultra は架空の製品であり、仕様・画像・動画・ロゴは仮置きのダミーとする（決定記録 2026-10-16 DR-ASM）。画面の見た目（色・タイポグラフィ・ヒーロー・カード）は、2026-10-19 の依頼により、公開されている Microsoft Surface のブランド表現（SRC-008、SRC-009）と Microsoft Fluent 2（SRC-005）に沿わせる（決定記録 DR-BRAND、NFR-UX-004、NFR-UX-005）。パートナー向けのブランドキット（SRC-010）は認証が必要で未取得。

### 1.3 事業妥当性の判定

条件付き。デモ用途であり、事業数値（売上・利用者数・費用）は入力がないため設定しない。条件: (1) Surface Ultra は架空でありブランド素材・仕様は仮置き（実在の製品として公開しない）、(2) Azure Speech のキーは利用者が環境変数で提供し、キーがない場合でも他の機能が動く（FR-006）、(3) 受益者・決定権者は利用者（デモの主催者）、費用負担者は利用者。

## 2. 対象と対象外

対象:
- 1 つのシェルと、画面上部のトグルによる App1 / App2 の切替（FR-001）。
- App1: 価値説明、公式動画（任意）、利用シーン、CG アニメーション、ナレーション、多言語、ペルソナ別全画面プレゼンテーション。
- App2: 企画・見積・制作プロジェクト・外部発注・素材・チャネル展開・KPI/OKR・利用状況の管理と可視化、変更履歴、what-if。
- 両アプリ共通: 2D/3D の表示方法切替、カメラワーク選択、ワークスペースのレイアウト変更、ペルソナ別の情報表現。
- Speech トークンを発行する軽量バックエンド。データはシード JSON。

対象外:
- ログイン・認証・認可（認証なし。依頼原文）。
- 実在の Surface Ultra の公式情報の入手（架空として仮置き）。ブランドの見た目は、2026-10-19 の依頼で対象に入れたが、入手できる範囲は公開資料（SRC-008、SRC-009、SRC-005）に限る。認証が必要なパートナー向けブランドキット（SRC-010）の取得と、Microsoft のロゴ・シンボルの使用（商標ライセンスが必要。SRC-008）は、利用者が提供・許諾するまで対象外（Q-003、Q-004）。
- 外部システムへの書き込み、デプロイ、有料サービスの契約。
- 本物の外部発注・決済・広告配信。データはモック JSON で、変更はブラウザ内（localStorage）にだけ保存する。

## 3. 前提・制約

### 3.1 既定制約（要求定義プロンプトの常設方針）

- ui_policy-1 利用者がレイアウトを変更できるモダンな UI（決定状態: 承認済み・既定制約）
- ui_policy-2 ペルソナごとの既定の情報表現（決定状態: 承認済み・既定制約）

参照例: Visual Studio Code のワークベンチ（SRC-004）。能力の水準を示すためのもので、見た目の模倣ではない。

アプリ固有の既定制約（依頼原文・SRC-001、SRC-002）:
- 技術: React + TypeScript + Vite、Fluent UI（Microsoft Fluent 2 のコンポーネントとカスタムブランドのテーマ、SRC-005。見た目は、App1 は Surface のリッチなブランド表現、App2 は同じブランドの色・書体・形を使いながら業務画面として情報密度と操作性を優先した表現とする（NFR-UX-004）。2026-10-16 の「落ち着いたデザイン」は 2026-10-19 の依頼で置き換えた（DR-BRAND））、three.js / React Three Fiber（3D）、Framer Motion（動き）、Speech トークン発行の軽量 Node バックエンド。
- Azure Speech のキーはコミットしない。環境変数で渡し、クライアントに出さない（NFR-SEC-001）。
- 対応言語: 日本語（ja）、英語（en）、中国語（zh）、韓国語（ko）。
- 認証なし。「ログインユーザーの言語」はブラウザの言語設定で代替する（決定記録 DR-LANG）。
- データはシード JSON（モック）。状態の保存はブラウザの localStorage（決定記録 DR-STORE）。
- ブランドの指針（依頼 2026-10-19・DR-BRAND）: 見た目は Microsoft Surface の公開のブランド表現（SRC-009）と Fluent 2 のカスタムブランドのテーマ（SRC-005）に沿わせる。Microsoft Surface のロゴの使用には商標ライセンスが必要で、ロゴはサイズ変更以外に改変しない、周囲に Microsoft シンボル 1 個分のクリアスペースを取る、明るい背景ではグレー・暗い背景では白のロゴタイプの版を使う（SRC-008）。ライセンスと公式のロゴファイルがない間は、Microsoft のロゴ・シンボルを自作・再現しない（NFR-UX-005）。シェルと App2 も同じブランドの見た目（主色・書体・ピル形のボタン・角丸のカード・明るい面・暗い面と光のグラデーションの帯）を使い、App2 は全幅のヒーローと装飾の出現アニメーションを持たずに情報密度と操作性を優先する（NFR-UX-003、NFR-UX-004、DR-BRAND）。フォントファイルは同梱も外部からの読み込みもしない（PARAM-013、PARAM-014）。

## 4. ペルソナ

## 5. 利用シナリオ

- 主な流れ（App1）: 利用者がサイトを開く → ブラウザ言語で表示される → 価値説明を読む → 製品の 3D/CG を見る → ナレーションを再生する → CTA で公式サイトへ進む。
- 主な流れ（App2）: トグルで App2 に切り替える → 制作プロジェクトの進捗・予算・KPI を見る → 企画・見積を変更し版が残る → what-if で KPI を試算する → 素材を登録しチャネルに紐付ける。
- 代替の流れ: 3D が使えない端末では 2D 固定で同じ情報を見る。Speech が使えないときはブラウザ音声または字幕だけで続ける。
- 中断と再開: 言語・表示方法・カメラワーク・レイアウト・編集中のデータは localStorage に保存され、再訪時に復元される。
- 変更と取消: 企画・見積は版を新しく作り、旧版へ戻せる（FR-014）。レイアウトは既定に戻せる（FR-010）。
- 失敗と復旧: トークン発行失敗・WebGL 非対応・動画なしのとき、利用者に状態を示して代替（フォールバック）に切り替える（NFR-UX-002）。
- 支援への引継ぎ: 認証・問い合わせ窓口がないデモのため対象外。
